## Prioritized findings

### 1. P1 — Global origin lookup breaks connection and owner isolation

**Proven by control flow:** `src/agent-chat/tower-transport-runtime.ts:18–32` scans `backendConnectionStore.listAll()`, matches origins without manager/subscription/connection context, rejects any differing configuration, then selects `matches[0]`. `tower-client.ts:474` and `flightdeck-pg/client.ts:691,817` use this lookup. Owner checks on the new API do not constrain it.

Reproduction setup for a focused regression: owner A has an HTTPS connection to origin T; owner B creates their own connection to T and selects FIPS (or merely a different expected identity). Every A request to T now throws the conflicting-approvals error, despite A changing nothing. With equal configurations, requests for both records accrue to one record's transport; `serialiseBackendConnection` (`src/server/agent-chat-routes.ts:144`) and event diagnostics address each record separately. Test connection can therefore return diagnostics for a different instance from the one performing its workspace read. This is an availability/isolation defect, not a demonstrated ACL bypass or signature theft.

**Minimal direction:** carry an explicit authorized connection ID through client/signing/request context. Resolve one record and bind target preparation plus send to that transport generation. Scope CLI/MCP resolution to the assigned connection. Test two owners with the same Tower origin, differing modes, separate counters, and a switch affecting only the selected connection. Reject ambiguity within the caller's authorized context, not across all owners.

### 2. P1 — Applying transport restarts disabled subscriptions and bypasses normal subscription routing

**Proven by control flow:** `tower-connection-settings.ts:43–45` reconnects every linked subscription. `subscription-runtime.ts:1445–1449` directly calls `ensureFlightDeckPgConnected`. Disabling a subscription persists `sseStatus: 'disabled'` (`2975–2982`), but the new reconnect path does not preserve that state. `ensureFlightDeckPgConnected` (`3513–3540`) only excludes `wsKeyStatus === 'failed'`, then saves `connecting` and starts polling. Applying even the same config re-enables an explicitly disabled subscription.

It also bypasses `ensureConnected`'s revocation and PG-versus-legacy checks (`3483–3495`). An existing non-PG subscription is stopped and sent into a PG loop that exits without a workspace ID (`3834–3836`); explicit HTTPS application can therefore break legacy behavior. A revoked record is allowed further than the normal guard, although subsequent Tower access checks may still deny it; no authorization bypass is claimed.

**Minimal direction:** preserve disabled/revoked state and dispatch active subscriptions through the existing guarded connection method. Add disabled PG, revoked PG and legacy HTTPS switching regressions. Handle reconnect failures per subscription so one missing bot identity does not prevent the remaining linked subscriptions from reconnecting after the config has already committed.

### 3. P1 — Existing connection health still accesses the public endpoint outside transport accounting

**Proven reachable bypass:** `tower-client.ts:2184–2210` defaults `checkBackendConnectionHealth` to ordinary `fetch`, uses `record.healthUrl`, and neither consults transport nor rejects redirects. `subscription-runtime.ts:3160,3177–3182` invokes it when creating/reusing backend connections. A reused connection retains `transport` through the spread at `3145`, while keeping or refreshing its public `healthUrl` at `3156`.

Thus re-onboarding/reusing a FIPS-selected connection with a public health URL performs a public request independently of selected mode, mesh availability and adapter counters. This is not a claim that every polling iteration probes public health, or that the new Test button uses this old function. FIPS-only creation also leaves old health diagnostics degraded because no health URL is populated.

**Minimal direction:** make this connection-specific health path use the selected adapter and its diagnostics; do not invent a public endpoint. Test reusing a migrated FIPS connection with a retained public health URL and assert zero direct fetches/redirects.

### 4. P1 — PG SSE implementation is not activated by the runtime

**Proven requirement gap, pre-existing dormant path:** `ensureFlightDeckPgConnected` (`subscription-runtime.ts:3540`) launches only `runFlightDeckPgEventLoop`, which repeatedly calls `fetchFlightDeckPgEventsImpl` (`3868`). `runFlightDeckPgLiveEventLoop` at `3693` contains the SSE call at `3713`, but a repository search finds no invocation of that method. Updating the SSE adapter and its unit test does not activate production SSE.

The current runtime is polling-only. An acceptance phase that drops an Autopilot SSE connection cannot prove recovery polling unless it first establishes that such a stream exists. The source predates this commit, but delivering SSE plus recovery is an explicit requirement for this implementation.

**Minimal direction:** explicitly wire the existing SSE and recovery machinery into one generation, retaining shared queue/cursor/deduplication, or have the manager resolve a polling-only scope change. Do not label a polling-only run an SSE recovery pass. Require evidence of an established stream, forced stream loss, and a fresh event delivered by mesh polling exactly once.

### 5. P2 — Transport switch does not invalidate in-flight event processing callbacks

**Proven missing guard; loss/duplicate outcome not reproduced:** generation checks surround poll receipt (`subscription-runtime.ts:3886`), but `handleFlightDeckPgEvent` (`3945–3995`) and `processFlightDeckPgEvent` (`3998–4104`) accept no generation/signal. An already awaited hydration/task/document handler can continue after the new switch aborts the transport. The final event in a poll batch returns to cursor/health writes (`3895–3912`) without another generation check. Hydration itself carries no signal (`direct-chat-tower-hydration.ts:47–64`), so its next request may resolve against the newly selected transport.

Existing per-subscription queues, in-flight event keys and monotonic event cursor checks are useful protections; they do not prove stale callback rejection. Do not discard already committed durable work when fixing this.

**Minimal direction:** carry/check a generation token across asynchronous processing and before generation-owned diagnostic/cursor saves, or explicitly drain durable event processing before switching. Add a blocked-hydration/last-event switch test and preserve publication idempotency. Lost-response duplicate dispatch remains an acceptance gap, not a reproduced bug here.

### 6. P2 — CLI traffic is not included in host diagnostics and relies on a local database implicitly

**Proven architecture limitation:** `src/flightdeck-pg/cli.ts:60` constructs the shared client, but transport lookup dynamically opens the module-local store (`tower-transport-runtime.ts:20`), whose database path is fixed to `../../data/wingman.db` (`storage/message-store.ts:113`). Transport instances/counters are a process-local map (`tower-transport-runtime.ts:5`). An ordinary CLI child sharing this checkout can find persisted approvals but its request/error counters never appear in the host settings API. A CLI installed in another checkout/runtime has no supported connection-context lookup through `wingmanUrl`; unmatched public URLs go directly to fetch (`tower-transport-runtime.ts:28–31,42`), while unmatched FIPS URLs fail approval.

**Minimal direction:** route associated CLI requests through the host's scoped broker/transport, or explicitly provide authorized connection configuration and report centralized telemetry. Add a child-process CLI test, not only an in-process client test. This prevents using host counters as evidence of all Autopilot-originated requests; independent network evidence remains mandatory.

### 7. P2 — Settings refresh discards unsubmitted transport approval fields

**Proven UI flow:** `workspace-settings-section.js:84` refreshes every 30 seconds; `renderSnapshot` replaces all children (`177–182`) and rebuilds the transport card from persisted config. The card's unsaved endpoint/npub values exist only in its input elements (`tower-transport-card.js:12–29,44`). A background refresh during manual approval entry discards them; the transport card is recreated without restoring its draft. This is particularly disruptive for long endpoint/identity values.

**Minimal direction:** persist the nonsecret draft separately in Dexie and retain it through diagnostics refresh, clearing it after successful apply/cancel. Also gate transport controls by actual connection ownership, not only generic `snapshot.canManage` (`workspace-settings-section.js:179`); the API correctly rejects foreign owners but the model omits ownership and offers controls that cannot succeed. Test editing across a timer refresh and viewing a shared connection.

## What the current core gets right

- The new side-table config is saved in the same SQLite transaction as the backend record (`backend-connection-store.ts:175–232`). Legacy records normalize to HTTPS; new FIPS-only creation uses the approved mesh endpoint as its logical URL and persists `httpsEndpoint: null`. No invented public hostname is required by this constructor. Existing IDs/cursors are not rewritten by settings save. Full FIPS-only workspace onboarding and UI discoverability still need acceptance: the card is only rendered for existing workspace subscriptions and Test requires a linked workspace (`subscription-runtime.ts:1460–1462`).
- `tower-transport-config.ts:10–27` checks canonical checksummed identities and strict `.fips` origin/port syntax. Mesh node identity comes from the endpoint; health is compared to a separately configured service identity. TCP is pinned to the `fipsctl`-derived IPv6 address while Host/path/query are retained (`native-fips-request.ts:17–50`). `/health` is an unsigned identity assertion trusted through the approved node, not cryptographic proof that the node controls the service key.
- Shared PG signing prepares the selected target before requesting the capability signature (`tower-client.ts:474–480`; `flightdeck-pg/client.ts:96–108` sends exact target/body hash to the broker). Kind-33358 instruction-signature construction remains present. No grant broadening or new raw-key workaround was added by this diff. Existing runtime-local signing branches remain; real broker acceptance must exercise the capability branch separately.
- Registered transport fetches reject redirects; native HTTP sends exact serialized body bytes and does not forward an HTTP request to a redirect destination. The FIPS wrapper rejects a mismatched signed `u` target. No HTTPS fallback is present inside `TowerTransport`. This positive finding does not cover the origin-lookup/direct-health bypasses above or arbitrary unmatched URLs.
- Attachment prepare/upload/complete use the shared adapter and authenticated Tower object routes (`tower-client.ts:1209–1300`); upload does not follow a returned presigned target. FIPS downloads select authenticated content instead of the returned S3 URL (`flightdeck-pg/client.ts:774–776`). HTTPS retains direct presigned fetch with default redirects (`777`), so external storage remains an explicit HTTPS dependency with an unapproved-destination/redirect test gap. No Tower Authorization header is passed on that presigned fetch. No all-attachment-bytes/ACL assertion is established without real object tests.
- Native requests combine abort signals; ordinary response bodies retain a bounded deadline and SSE clears its header deadline after headers (`tower-transport.ts:107–149`). Closing the transport aborts its native stream. Shared verification uses its first caller's signal; subsequent callers do not get independently cancelable waits, and signing preparation has no caller signal. These cancellation cases need focused tests, not a claim of an observed hang. macOS runtime inspection is not itself passed the request abort signal.
- The new mutation/test routes check management permission and exact record ownership (`tower-transport-routes.ts:17–27`, `tower-connection-settings.ts:6–10`). Selected/effective mode, identity and counters are exposed without deliberately including request bodies/authorization. The card uses accessible labels/test IDs/live status, and the existing dynamic `.js` static handler supplies `application/javascript` (`static-assets.ts:293–296`). No new MIME defect found.
