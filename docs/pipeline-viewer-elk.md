# Native viewer ELK proof of concept

The `/pipelines` definition and run viewer lays out accessible HTML cards with
ELK.js orthogonal SVG connections. The browser measures each card and field,
then supplies fixed-position field ports to the layered layout algorithm.
Desktop layout flows right with output ports east and input ports west; narrow
viewport layout flows down with both sides on the east card boundary. Mobile
edge labels rotate vertically into space reserved by ELK. The value drawer
is an overlay and does not change graph dimensions.

Connections describe configured selectors, independently of captured execution
status. Solid lines show data mappings; dashed lines show carried fields. Field
selection highlights connections without running layout again. Exact selectors
missing from display metadata appear as distinct dashed fields. Unknown field
names remain paths. A visible Pipeline input or Scope input card supplies paths
whose source is outside the displayed scope. Whole-object mappings expand the
receiving display fields first rather than implying every upstream preview field
is a separately named receiving field. No card or arbitrary-field fallback
is used when an exact endpoint is unavailable. The defined-order caption does
not imply unconditional execution. Child scopes and captured run children keep
separate navigation and the existing evidence inspector.

Layout generations reject stale results and disposal invalidates pending work.
Unchanged measured graphs reuse layout across hover and run refresh. Retained
private values remain transient; evidence requests, redaction refusal, identity
checks and Dexie summary storage continue through the existing viewer session.

## Bundle provenance

`elkjs` is pinned to **0.11.0** in package.json and bun.lock. The checked-in
`src/ui/pipelines/elk-bundle.js` is generated by `bun run build:pipeline-elk`
from `scripts/pipeline-elk-entry.ts` using Bun's browser ESM bundler. The build
rewrites multiline literal templates with trailing whitespace into equivalent
quoted strings using the TypeScript AST, preserving cooked string values. It includes
the bundled in-process ELK implementation; there is no CDN import or worker
asset request. ELK.js is licensed under EPL-2.0; its complete license is included
in `src/ui/pipelines/elk-license.md`. Upstream source:
https://github.com/kieler/elkjs (tag v0.11.0).

The existing generic static service serves `/pipelines/elk-bundle.js` and the
other `/pipelines/*.js` modules as `application/javascript`. Activation requires
browser reload, with no route registration or server restart.

## Provider-free validation

`scripts/pipeline-native-bird-definition.json` and
`scripts/pipeline-native-bird-timeline-definition.json` freeze real local Bird
retrieve and timeline/chat v2 definitions. The isolated browser fixture expands
these definitions without running them or calling Bird/providers. Separate
synthetic retained runs exercise values, attempts and privacy. The production
shell and static handlers are reused; this does not establish owner-authenticated
live-data acceptance.

Large graphs preserve card/field readability and scroll rather than fitting by
shrinking. Paths are shown on SVG edges and configured fields. Historical runs
without captured wiring retain recorded steps but cannot reconstruct missing
configured links. ELK layout failures are reported visibly.

Some existing viewer DTOs omit default state-input mappings (for example the
Bird parent loop and chat invocation block). Displayed inputs with no captured
exact source selector are explicitly marked mapping unavailable. The browser
does not infer those links from step order or child implementation. The frozen
Bird chat definition carries separate workspaceId, threadId, frmNpub and prompt
fields, so these actual selectors are exposed rather than inventing one
chatMetadata field. A definition that explicitly maps chatMetadata gets its own
connected field.
